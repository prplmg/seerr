# Shared daily homepage list rotation — 2026-11-06

Implemented locally, tested, not deployed. No production data, import schedules or user toggles changed. Only point 3 of the list agenda is addressed; other pending browse/curation work remains excluded.

User decision: identical cards/order for everyone, including owned/saved lists. Prefer 20 cards, but allow more to represent all eligible users with different public saved/created lists.

Selection is deterministic for the America/Merida calendar date, independent of requesting user or input order. It recomputes on a normal API request; no timer reshuffles an open row in place. First select up to ten verified Letterboxd lists from the whole eligible pool, replacing the old static-seed preference. Then find distinct representatives among eligible users' public created or saved lists. Shared lists appear once; where different candidates exist a matching algorithm avoids consuming another user's only option. A list already in the Letterboxd block can represent a user when no additional distinct candidate exists. These user picks may themselves be Letterboxd lists, so ten is the general discovery allocation, not a hard source-total cap. Finally add curated lists until20. User representation may exceed20; insufficient eligible inventory yields a shorter row, never duplicates or private content.

Private/unknown/unavailable/deleted/stale and both editorially excluded URLs remain excluded. Uniform public freshness rules also apply to owners (whose library visibility normally permits stale/private owned lists). Existing social privacy still governs whose saves/created lists qualify for representation: the server supplies one common eligible-user set, without adding hidden viewers back into it. No association identities are returned. Individual watched/progress/save states remain personalized. Full Explore results/search and all other recommendation rows are unchanged.
