# AI Search sorting — local only, 2026-11-08

Permanent arrows-up/down control at the right of the filter chips. Popover offers Best match, Letterboxd score, runtime and release year, direction, plus one optional distinct Then by field. Current order is visible beside the icon; initial inferred order is labelled Suggested from your search. No deployment or toggle changes.

Local deterministic prompt rules select explicit sorting first, then clear directional clues and one-sided score/runtime bounds. Neutral score ranges and year ranges alone keep relevance. Minimum score defaults descending; maximum score ascending; recent/newest descending year; oldest ascending year. Short and highly rated favors rating with runtime remaining a filter. Common English wording is supported; uncertain phrasing retains Best match and can be corrected manually. No model-contract/cache-key changes or additional model calls for sorting.

The existing search endpoint accepts a validated maximum of two distinct sort fields. Manual sort changes send existing filters and require the cached interpretation; they cannot silently invoke AI. Requests still recheck catalogue visibility/filters. Sort applies to the same at-most-20 returned shortlist, not a catalogue-wide ranking. Missing values sort last in either direction; complete ties preserve initial relevance. Best match restores original order. New submissions and History reopens infer from original prompt filters; Back restores the full response including manual order without a request.

Missing scores use the existing four-worker list-score cache/queue. Runtime collection uses the same queue with its existing two-runtime/four-total limit, including episode runtimes for series. Generalized completion notifications wake runtime waiters as well as score waiters. Existing cache persistence and deadline behavior retained. Unknown sort-only metadata does not remove a title. Runtime badges appear for runtime sorting too.
