# Weekly automatic Letterboxd lists

Scope: the new automatic list system only, based on live commit 7b8cf3ef. No pending collection additions, media-detail/list UI, category filters or rotation changes.

Tuesday 07:20–08:40 America/Merida starts a complete eight-page census (first two pages of all-time, weekly, monthly and yearly popularity). The existing read-only Edge extension, in an anonymous InPrivate window, supplies URL/title/film-count evidence. Any eligible linked profile may do this; no account publishing toggles change. The job remains in Seerr's scheduler. A minute tick during hours 07/08 checks the explicit window; unfinished work resumes in the same morning window on following days. Other days do not start new weekly cycles. Missing Plex health or active Plex activities/catalogue heavy scans defer work.

Only complete successful discovery evidence reconciles the pool. Lists with 1–560 items qualify; larger lists are skipped, never truncated. One automatic list is outstanding at a time. A first-page count rechecks growth before pagination. Metadata requests have 250ms pacing and a checkpoint between films; an already-issued network request may finish after the cutoff, but new metadata work stops. The public list snapshot is retained for resumption. Valid film identities persist for 90 days, bounded to 20,000 cache entries; errors/ambiguous matches are never cached. Pure list public checks need no film lookups, and discovery pages themselves establish current public appearance.

The existing static seed refresh stays active until the first successful weekly census, then yields to this queue. Personal saved/liked/owned list refresh remains on the existing twice-daily job, with its existing batch controls. A weekly failure retains the previous snapshot. Browser jobs unavailable for a day can retry; discovery has three morning attempts; a failed complete probe never causes retirement. Content jobs have at most three retries and retain their prior snapshot on failure. Errors stay in weekly-lists.json and logs.

Automatic lists absent from qualifying discovery for two weeks are removed only after a complete successful probe and only if they are not saved, liked or owned. References are rechecked immediately before removal. Existing static seeds receive a two-week grace period when adopted. Unsaved automatic list history keeps the latest snapshot instead of accumulating 60 full copies. Personal list history remains unchanged. Automatic public visibility uses a 15-day freshness bound (rather than the personal daily bound), so weekly refreshes remain visible between runs. Retired unreferenced identity records are pruned; successful match cache expiry prevents indefinite metadata growth.

Files: weekly-lists.json holds resumable census/queue/last-seen state; weekly-film-matches.json holds reusable matches; discovery-browser.json retains authenticated read-only delivery claims. These do not contain browser cookies. Installation adds extension 0.2.49 with no new permissions; the installer requires exact live file hashes, idle worker, a narrow bridge restart and unchanged binding/config hashes. Rollback restores the six worker files from its receipt plus the catalogue release rollback.

Validation and release receipt follow in docs/benchmarks/weekly-lists-20261106. All six users' existing toggle settings must be verified unchanged after rollout. No Git push is implied.
