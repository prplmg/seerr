# Normal-startup PostHog trial

Implemented and deployed November 10, 2026. Current live build: 1J9J9K5Ye6fznmCFWON0p. See ../../deployments/posthog-explicit-20261110/receipt.md.

All authenticated users now default to events plus replay. Random assignment is removed, including all reads of legacy randomized session keys. Admins can explicitly select Off, Events only or Events + replay in Profile → Settings → Analytics test mode. Selection is scoped to the current tab and signed-in user, persisted in sessionStorage and applied with a full reload. Non-admin users ignore saved overrides. Returning to Events + replay removes the override. Existing privacy exclusions and masking remain. The experiment identifier is explicit-modes-v2.

Startup occurs on normal React mount after authentication/settings are available, without idle or interaction deferral. Off never requests the SDK. PostHog 1.447.7 is loaded asynchronously from its regional CDN in enabled modes.

Runtime configuration: POSTHOG_TRIAL_ENABLED=true, POSTHOG_PROJECT_TOKEN (browser project token), POSTHOG_HOST=https://us.i.posthog.com. Default is disabled. Configuration travels with existing public settings, so there is no extra startup config request. To stop the trial, set enabled=false and restart the app; existing open documents need refreshing. No existing notification or sync toggles change.

Pageviews cover discovery, For you, Find something to watch, AI search, movie and series detail. Explicit actions currently cover opening comments, opening reaction pickers and editing reviews. Autocapture, heatmaps, surveys, exception capture and PostHog performance collection are disabled. User identity is the catalogue numeric ID, not email/name. Query strings and media IDs are removed from event URLs. Other routes stop capture; replay also stays off on query-bearing URLs. Replay masks text and blocks inputs, textareas, contenteditable and ph-no-capture elements. Events-only explicitly disables recording; replay is started programmatically only in its group. Project-level replay must also be enabled.

Independent measurements run in all modes: FCP, LCP, long-task count/duration, largest observed event duration (not a full INP implementation), SDK timing/failure and viewport width. Unsupported browser measurements remain absent. Up to ten cumulative reports per document, at 30-second intervals or when hidden/cleaned up, go through the authenticated API to existing rotated server logs. No new database writes. Reports must be deduplicated by session/document timing when analyzing cumulative totals. Current measurements describe document startup and cumulative interaction work, not individual SPA navigation readiness or server CPU. Small samples cannot establish negligible overhead.

Validation: TypeScript check; focused lint; actual component in Chrome with mocked SDK for off/events/replay; actual Express route with full OpenAPI validator, rejecting extra/private fields and taking identity from the authenticated session. Cloud ingestion and actual live replay remain deployment verification work. Earlier isolated real-SDK benchmark results are separate from these integration tests.
